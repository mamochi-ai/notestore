# わたしの小さな本屋

noteに書いた記事を、一冊ずつ本にして棚に並べるWebアプリです。
表紙・背表紙・店主のPOPから作品を見つけてもらう「本屋」をつくり、自己紹介記事で紹介できます。

- **AI API・有料API・専用サーバー・ログイン・DBサーバーは使いません。** 静的ファイルだけで動きます。
- 取り込んだファイルはブラウザの中だけで処理し、どこにも送信しません。
- データは端末のブラウザ（IndexedDB）に保存します。バックアップZIPで別の端末へ移せます。
- iPad・iPhoneのSafariで使う前提で作っています（ビルド作業は不要）。

---

## 1. 公開して使う（iPad・iPhoneだけでできる手順）

このリポジトリをGitHub Pagesで公開すると、SafariでURLを開くだけで使えます。

1. GitHubのリポジトリ画面で **Settings → Pages** を開く
2. 「Build and deployment」の Source を **Deploy from a branch** にする
3. Branch で公開したいブランチ（例：`main`）と **/ (root)** を選んで Save
4. 数分後に表示されるURL（例：`https://<ユーザー名>.github.io/notestore/`）をSafariで開く
5. 共有メニューの「ホーム画面に追加」をしておくとアプリのように開けます

> 補足：このアプリ自体のURLを公開しても、あなたの本屋のデータは公開されません（データは各端末の中だけにあります）。

### パソコンでの確認（任意）
```
node tests/serve.mjs 8123
# → http://localhost:8123/ を開く
```

## 2. 基本の流れ

1. noteでエクスポートしたZIP（XML＋画像）またはXMLを「noteの記事を読み込む」で選ぶ
2. 記事の確認画面で、本にする記事を選ぶ（公開記事だけが最初から選ばれています。下書き・予約・状態不明は選ばれていません）
3. 「整理の提案」で、連載のまとめや棚分けの候補を必要なものだけ選ぶ（タイトルの規則で機械的に出した候補です）
4. テーマ（6種類）を選ぶ
5. 本棚を編集：本をタップ →「装丁・POPを編集」、表紙向き/背表紙向き、おすすめに飾る、移動先、前へ/後ろへ、長押しドラッグで並べ替え
6. 「プレビュー」で訪問者からの見え方を確認
7. 「シェア」から共有（下記）

## 3. 共有の3つの方法

| | 中身 | 画像 | 本文 | 必要な作業 |
|---|---|---|---|---|
| **A. 本棚の画像** | 選んだ棚と店名の一枚画像（長い場合は分割） | 描かれる | なし | 画像を保存して記事に貼る |
| **B. 紹介リンク** | 店名・テーマ・選んだ本のタイトル/noteのURL/POP/紹介文を圧縮してURLの `#` 以降に入れる | **入らない**（文字の表紙で表示） | **入らない** | なし（サーバー不要） |
| **C. 公開用ZIP** | 選んだ本・装丁画像・閲覧ページ一式 | 入る | 許可した本だけ | ZIPの中身を静的ホスティングに置く |

- B は手軽な紹介版、C は装丁を保った完全版です。
- B のURL長は保守的に **8,000文字まで** にしています（Chromiumで確認。iPhone/iPad実機Safari・各メッセージアプリでの上限は未確認）。超えたときは減らす冊数の目安を表示します。短縮URLは作りません。
- C は **自動ではURLが発行されません**。ZIPを展開し、中身をGitHub Pagesなど（別リポジトリでも可）に置いてください。本屋を更新したらZIPを作り直して置き直します。
- どの方法でも **本文は最初はオフ**。下書き・予約・状態不明の記事は共有対象にできません。本文を公開する場合は本ごとに本人が選び、有料部分がないことの確認チェックが必要です（noteの書き出しには有料部分の境界・価格が含まれないため、自動判定はしていません）。
- 共有リンクを開いても、開いた人の端末の本屋は上書きされません。共有データはサイズ・型・URL（https://note.com のみ）を検証してから表示します。

## 4. 保存とバックアップ

- 「お店の設定」→「バックアップを書き出す」で、画像・本文・設定を含むZIPを保存できます（iPhone/iPadでは共有シートから「ファイルに保存」）。
- 新しい端末では、最初の画面の「バックアップから復元する」または「お店の設定」→「バックアップから復元」。
- Safariの「履歴とWebサイトデータを消去」やストレージ不足で端末のデータが消えることがあります。定期的なバックアップをおすすめします。
- 保存に失敗したときは編集バーに「⚠ 保存できませんでした」と表示します（保存できたふりはしません）。

## 5. noteエクスポートの取り込みについて（確認できた範囲）

**実物のエクスポート1件（WXR 1.2形式のXML＋assets/、21記事・画像46枚）で動作を確認済み**です。それ以外の形式は防御的に扱いますが、対応済みとは言えません。

- XMLは名前空間を考慮して DOMParser で解析（正規表現で解析しない）。`<!DOCTYPE>` / `<!ENTITY>` を含むXMLは拒否。
- 取り出す項目：タイトル、本文（content:encoded）、日時（post_date_gmt → post_date）、記事URL（link）、状態（wp:status）、guid（noteの記事キー、再取込時の照合に使用）。
- **見出し画像**：本文の先頭が `<figure><img>` で、ファイル名が `{記事キー}_{32桁の16進}.拡張子` のときだけ見出し画像と判定（実データで観察した規則）。本文の最初の画像を無条件に見出し画像にはしません。判定できない記事は文字の表紙になり、装丁編集で本文の画像から選べます。
- 画像パスは `/assets/…`、`./assets/…`、URLエンコード、ZIP内の上位フォルダの有無に対応。同名ファイルが複数あるときは自動で決めず、装丁編集で選びます。
- XML単体の場合は画像なしで取り込みます（文字の表紙）。
- 本文中の外部画像は**自動で読み込みません**（「画像を開く」リンクに置き換え）。
- URLは公開記事の `link` だけを使い、推測で作りません。下書きにはURLを付けません。
- 再取込はguid（なければURL）で照合し、「新しい記事／更新あり／取り込み済み」を表示。更新は記事本文だけに反映し、**本のタイトル・装丁・POP・棚・連載の章順は変更しません**。
- 安全対策：ZIPサイズ600MB・ファイル数20,000・展開合計1.2GB・画像1枚40MB・画素数6,000万までの上限、パストラバーサル（`../`、絶対パス等）のファイルは無視、取り込んだHTMLは許可リスト方式で再構築（script・iframe・イベント属性・style・javascript: 等は除去）。

## 6. 本と読書

- 通常記事は1記事＝1冊。連載・短編集は複数の記事を選んで1冊にまとめ、章の順番を変更できます。まとめを解除すると元の本（装丁・POPも）に戻ります。
- 本のタイトルは元記事のタイトルとは別に保存されます。背表紙用の短いタイトルは自動（【見出し】や（…）を除く）で、自分でも設定できます。
- 縦書き/横書きを本ごとに設定し、読書中にも切り替えられます。縦書きは章ごとの横スクロール方式（ページ分割はしないので、文字サイズ変更や回転で本文が欠けたり重複したりしません）。2桁までの数字は縦中横。ルビは元データにある場合のみ表示（創作しません）。
- 本文は画面中央の紙面に表示します（PC・iPadは最大幅あり、iPhoneは画面幅を使用）。縦書きは紙面の右から読み始め、長い章は紙面の中で右から左へスクロールします。
- 目次、前の章/次の章、文字サイズ、行間、しおり（端末に保存・目次から「しおりの位置へ」）、続きから表示、縦書きでの画像・表の表示切替。
- 本の詳細：連載状況・章数・**読了目安（本文の文字数 ÷ 500字/分、`app/js/readtime.js` で一元管理）**、短い紹介文、**こんな人へ**、店主のおすすめ理由（従来の「店主のPOP」と同じ項目）。未入力の項目は表示しません。目次の各章をタップするとその章から開きます（本文の無い章はnoteへのリンクのみ）。

## 7. お店らしさ（誰の本屋でも同じにならないための機能）

| 機能 | 設定する場所 | 内容 |
|---|---|---|
| 帯 | 装丁編集「紹介・おすすめ」 | 本の下部に帯を巻く（文字30字・色）。表紙・背表紙・平積みのどれでも見える |
| 置き方 | 本を選んで「置き方」 | 背表紙／表紙／**平積み**（続けて平積みにした本は同じ山に重なる）／**立てかけ**（右どなりにもたれる） |
| 分冊 | 装丁編集「読み方・公開」（連載のみ） | 章を順番どおりに均等に分け、「上・中・下」などの巻数つきで並べる |
| 日焼け | お店の設定 | 古い記事の本ほど背が少し褪せる。いちばん新しい本は褪せない。書いてきた期間が長いほど差が大きい |
| 本の厚み | お店の設定 | 「演出」または「本文の文字数」。文字数にすると長く書いた本ほど厚くなる |
| 看板・棚札の書体 | お店の設定 | 明朝／太明朝／丸ゴシック／角ゴシック（看板風）。端末に入っている書体を使う（手書き風の書体は同梱していない） |
| 店主の印 | お店の設定 | 店主名（または指定した最大4文字）から朱色の印を作り、店名の横・店主欄・今月の一冊・棚画像に押す |
| 今月の一冊 | 本を選んで「今月の一冊にする」 | 棚のいちばん上に飾る。添えることばは「お店の設定」で書く。月が変わると編集画面で更新を促す |

どれも任意で、既存のデータはそのまま表示されます。紹介リンク・公開用ZIP・バックアップ・棚画像にも反映されます。

## 8. ファイル構成

```
index.html              入口（CSPで外部スクリプトを禁止）
app/css/app.css         本・背表紙・紙/布/革の質感・棚・POP・読書紙面
app/js/main.js          起動と画面の切り替え（編集 / プレビュー / 閲覧）
app/js/shelf.js         本棚（棚PNGと本の座標合わせ、段の自動追加、ドラッグ並べ替え）
app/js/bookview.js      背表紙・表紙の描画（色・高さ・厚みは本IDから固定値で決定）
app/js/importer.js      noteエクスポート（ZIP/XML）の解析   app/js/sanitize.js  HTMLの無害化
app/js/import-ui.js     取り込み確認・重複/更新の判定      app/js/organize.js  連載・棚の候補（規則ベース）
app/js/editor.js        装丁・連載・棚・テーマ・お店の設定  app/js/reader.js    読書（縦書き/横書き）
app/js/share.js         共有A/B/C                          app/js/backup.js    バックアップ/復元
app/js/db.js, state.js  IndexedDB保存                      app/js/images.js    画像の検証と縮小
app/vendor/fflate.js    ZIP処理（fflate 0.8.2, MIT License, 同梱・CDN不使用）
assets/themes/*.jpg     キットの棚PNG（1536×1024）をJPEG化したもの（画像の比率・座標は同じ）
assets/ui/*.svg         キットのUI素材（ラベル・POPは伸縮できるよう preserveAspectRatio="none" を追加）
tests/                  E2Eテスト・テスト用の架空データ生成・簡易サーバー
```

## 9. テスト

```
node tests/e2e.cjs
# 自分のnoteエクスポートでも確認する場合（ファイルはリポジトリに入れないでください）
NOTE_EXPORT_ZIP=/path/to/export.zip node tests/e2e.cjs
```
Chromium（Playwright）での自動テストです。**iPad/iPhone実機のSafariでの確認の代わりにはなりません。** 結果は `docs/VERIFICATION.md`。
